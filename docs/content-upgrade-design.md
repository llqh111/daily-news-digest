# 设计文档：打破信息差 — 内容质量升级

> 状态：草案 v2（2026-06-11，信源已实测 + 提示词已重构）
> 作用：指导 daily-news-digest 从「英文要闻翻译器」升级为「有信息差的个人情报简报」。
> 阅读对象：未来的自己 / 帮忙改代码的 AI。
>
> v2 变更：§3 信源表全部经本地实测（标注 ✅/放弃原因/限量要求）；新增 §3.5 单源限量、
> §3.6 信任分建议；新增 §5.5 提示词重构（含可直接替换的完整提示词全文）。

---

## 1. 背景与问题定义

### 1.1 现状

当前流水线：20 家大众媒体 RSS → 关键词打分 → 同题聚类 → 抓正文 → DeepSeek 写中文晨报 → 微信/Telegram 推送。

### 1.2 核心问题：现在只有「翻译差」，没有「信息差」

BBC / Reuters / The Verge 的头条是全世界被转述最多的内容。当前唯一的优势是比中文媒体早 12-24 小时看到——这是时间差，不是信息差，且会随着中文媒体 AI 化逐渐消失。

信息传播链：

```
一手披露（监管/公司/论文） → 垂直分析师 → 英文大众媒体 → 中文媒体 → 微信群
     T+0                      T+0.5天        T+1天         T+2天      T+3天
```

**本项目目前卡在第 3 层。每往上爬一层，信息差多一天，噪声少 30%。**

### 1.3 信息差的三个来源（本设计的三大支柱）

| 支柱 | 一句话定义 | 对应章节 |
|------|-----------|---------|
| 源差异化 | 读别人没在读的东西 | §3 |
| 加工差异化 | 连接别人没连接的点 | §4 |
| 相关性差异化 | 对「我」独有的 so-what | §5 |

---

## 2. 设计原则

1. **不推倒重来**：所有改动都建立在现有打分/聚类/分批机制上，每个支柱可独立上线、独立回滚。
2. **配置即观点**：信源选择、信任分、个人关键词是「主编的口味」，放在 main.py 配置区，改数字不改逻辑。
3. **每条新增逻辑必须有测试**：沿用 test_core.py 的 TDD 模式。
4. **控制 token 成本**：每项改动注明对 DeepSeek prompt 体积的影响，总增量控制在 +30% 以内。
5. **前置依赖**：上线前先修完已知 🔴 问题（推送失败仍标记已发送、feedparser 无超时、CI 不跑测试）。地基歪的，往上盖什么都白搭。

### 3.2 配套机制改动

1. **`SOURCE_TRUST` 上限从 +2 提到 +3**：第 1/2 层源给 +3，确保它们稳进候选池（现有大众媒体最高 +2，不动）。建议值见 §3.6。
2. **新增 `feed` 级别的 `max_items` 字段**（可选，默认用全局 `MAX_PER_FEED`）：arXiv/OpenAI/HF 这类高产源单独限到 3，避免淹没候选池。实现见 §3.5。
3. **`MIN_PER_CATEGORY` 评估**：新增源几乎全是科技，上线后观察国际类是否被挤压，必要时把「国际」最低保留从 6 调到 7。
4. **每个新源先过 `test_rss.py` 连通性测试再进配置**，且**上 Actions 后再复测一次**——海外 runner 与本地结果可能不同（Reddit、墙内源尤甚）。

### 3.3 明确不做的

- **Money Stuff / The Information**：无公开 RSS 或全文付费，需要 newsletter 转 RSS 中转服务，复杂度不值得，Phase 3 再议。
- **X/Twitter 列表**：API 收费，放弃。
- **中文垂直源（36kr 之外）**：与「打破中文圈信息差」的目标相反，不加。

### 3.4 Token 成本影响

候选池大小由 `CANDIDATE_POOL` 钉死（15 条），加源只改变「池里是谁」，不改变池的大小。**成本增量 ≈ 0。**

> 注：本次用户决定「不卡 token 成本」，故 §4/§5 的提示词增量按更宽松处理。但 §3 加源
> 本身不增加喂给 AI 的条数（候选池固定），所以加再多源也不涨 token，只涨「抓 RSS + 抓正文」
> 的网络耗时。这也是为什么加源是性价比最高的一步。

### 3.5 单源限量（`max_items`）实现

arXiv（407 条）、OpenAI（997 条）、HF（797 条）若按全局 `MAX_PER_FEED=8` 取，仍会把
8 条论文/博客塞进候选，挤掉真要闻。给 `RSS_FEEDS` 的字典加可选 `max_items` 字段：

```python
# RSS_FEEDS 里高产源这样写：
{"name": "arXiv cs.AI", "url": "https://rss.arxiv.org/rss/cs.AI",
 "category": "科技", "max_items": 3},
```

`fetch_all_feeds` 里取数上限改为「源级优先，回退全局」：

```python
# 原： if count >= MAX_PER_FEED: break
limit = feed_info.get("max_items", MAX_PER_FEED)
if count >= limit:
    break
```

**可测**：构造一个带 `max_items=3` 的假 feed_info，断言最终取到的条数 ≤3。

## 4. 支柱二：加工差异化

### 4.1 跨天记忆——把「日报」变成「连续剧」（优先级最高）

**问题**：每期晨报都「失忆」。昨天写「美联储暗示降息」，今天写「降息 25 基点」，AI 不知道这是同一条故事线。而「事件的演变方向」恰恰是单篇报道给不了的、普通读者最大的信息差。

**设计**：

1. **晨报存档**：每次成功推送后，把生成的晨报全文写入 `digests/YYYY-MM-DD-{AM|PM}.md`。
   - workflow 的提交步骤从 `git add sent_articles.json` 改为 `git add sent_articles.json digests/`。
   - 保留最近 14 天，超期自动清理（复用 `save_sent_links` 的清理模式）。
2. **上下文注入**：调用 DeepSeek 前，读取最近 2-3 期晨报，**只提取每条新闻的标题行**（`**🔥/⭐ ...**` 格式行，正则可提取），拼成「近期已报道事件清单」，附加到 user prompt。
3. **提示词新增**（系统提示词【怎么用素材】一节追加）：

   > 我会附上「近期已报道事件清单」。若今天某条新闻是清单中事件的进展，必须以「📈 进展」开头，用一句话交代"此前→现在→变化意味着什么"，而不是当成新事件从头讲。

**Token 成本**：2-3 期 × ~20 个标题 × ~25 字 ≈ 1500 字 ≈ +1000 tokens/批。可控。

**风险与对策**：
- AI 可能把不相关新闻硬接到旧事件上 → 提示词强调「仅当确为同一事件时」；`sanity_check_output` 增加对「📈 进展」条目占比的统计（>50% 则告警，多半是误接）。
- 分批模式下每批都注入同一份清单，成本 ×3 → 可接受；若超预算，只在第一批注入。

### 4.2 立场交叉——用好聚类已有的原料

**问题**：`cluster_and_boost` 已经知道「这事被 BBC + 半岛 + SCMP 同时报道」，但目前只把簇大小用来加分，**簇内其他成员的标题被扔掉了**。不同媒体对同一事件的标题框架差异（措辞、归因、立场）本身就是高价值信息。

**设计**：

1. `cluster_and_boost` 给代表作新增字段 `cluster_titles: list[str]`——同簇所有成员的 `"来源: 标题"`（上限 4 条，按分数取）。
2. `_articles_to_text` 在「热度: 被 N 家媒体同时报道」之后追加：

   ```
   各家标题: BBC: xxx / Al Jazeera: yyy / SCMP: zzz
   ```

3. 提示词【深层逻辑】一节追加一句：

   > 若多家媒体标题框架明显不同（措辞/归因/立场），在【深层逻辑】中用一句话点出"谁在怎么说"。

**Token 成本**：仅多源簇（每期约 3-5 条）每条 +100 字 ≈ +300 tokens。很便宜。

**为什么这能破信息差**：单一媒体读者只能看到一种框架；「看出谁在怎么说」是媒体素养层面的信息差，比"发生了什么"更稀缺。

## 5. 支柱三：相关性差异化（个人雷达层）

**问题**：通用要闻人人都收到，无信息差。读者画像是「硬核游戏/MOD 玩家 + AI 编程学习者」，但 Steam 政策、引擎动态、显卡价格、开源模型发布在通用打分表里只有 +1，会被地缘大新闻挤掉。

**设计**：

1. **新增配置**（配置区，紧跟三个关键词表之后）：

   ```python
   # 个人雷达：读者私人关注领域，命中 +4（高于任何通用信号）
   # 这个表没有标准答案——只有你自己知道想盯什么。
   PERSONAL_KEYWORDS = [
       # 游戏 / MOD / 硬件
       "steam", "valve", "unreal engine", "unity", "modding",
       "rtx", "radeon", "dlss", "gpu price",
       # AI 编程 / 开源模型
       "claude code", "cursor", "copilot", "open source model",
       "local llm", "ollama", "fine-tuning", "api price",
   ]
   ```

2. **打分逻辑**：复用本次已上线的 `_compile_keyword_pattern` 整词匹配（不再有子串误命中问题），命中每个不同关键词 +4。
3. **提示词注入读者画像**（系统提示词追加）：

   > 读者背景：硬核 PC 游戏玩家、AI 编程学习者。命中标注「🎯 个人雷达」的条目，【后市/影响】必须落到对读者的具体影响（如显卡价格走势、工具链变化、可上手的新东西），而不是泛泛的市场影响。

4. **`_articles_to_text`**：个人雷达命中的条目加一行 `🎯 个人雷达命中: <关键词>`。

**效果示例**：同一条「英伟达发布新显卡」，输出从"股价上涨 3%"变成"50 系价格可能松动 + 本地跑大模型门槛下降"。

**Token 成本**：≈ +50 tokens。忽略不计。

## 5.5 提示词重构（整合三大支柱的完整新提示词）

§4/§5 把提示词改动拆散在各处描述。本节给出**整合后可直接替换 `_build_system_prompt` 的完整提示词全文**，避免实现时东拼西凑漏掉某条。

### 5.5.1 重构思路

现有提示词把所有要求堆在一起，AI 容易顾此失彼。重构遵循三个原则：

1. **分区职责**：角色 → 铁律 → 标记规则 → 写作格式 → 任务，块块分明。
2. **标记驱动**：先让 AI 给每条新闻打标记（🔥/🎯/📈/⚠️单一信源），再据标记触发对应写法——比纯文字描述更可靠。
3. **新指令各归其位**：跨天记忆指令进「素材处理」、立场交叉进「深层逻辑」、个人雷达进「后市/影响」，不再全堆末尾。

### 5.5.2 优化后的 system prompt 全文

> 替换 `main.py` 的 `_build_system_prompt()` 中 `base` 变量。`{reader_persona}` 在函数内用常量拼接（见 5.5.4）。

```text
你是一位资深的中文财经科技新闻主编，每天为一位高知读者撰写深度『晨报』。
你的风格像《财新》《FT中文网》：冷静专业，敢下判断、点出影响与看点，绝不做无观点的复述。

【读者画像——决定什么对他重要、影响该往哪落】
· 硬核 PC 游戏 / MOD 玩家：关注 Steam 与 Valve 动向、游戏引擎（Unreal/Unity）、显卡（RTX/Radeon/DLSS）与硬件价格。
· 正在学 AI 编程：关注大模型发布、开源模型、AI 编程工具（Claude Code/Cursor/Copilot）、API 价格与本地部署。
· 身处中国：所有国际/科技/财经事件都要主动评估「对中国市场、出海企业、国内供应链、本地玩家/开发者」的具体影响。

【深度思考要求（在正式输出前的内部推理中完成）】
1. 交叉比对：核对各篇素材之间的数据是否冲突，冲突时取多数或最权威来源并注明。
2. 过滤降噪：剔除洋八卦、标题党、纯软文，宁缺毋滥。
3. 连续性判断：对照我附上的「近期已报道事件清单」，判断今天哪些是旧事件的新进展。
4. 本土化与个人相关性：评估每条对「中国」和「上述读者画像」的具体意义。

【怎么用素材——这条最重要】
· 有【正文】的：通读后用自己的话写出来龙去脉，提炼关键事实、数据、人物、因果。
· 只有【摘要】的：据实简写，明确不脑补正文里没有的细节。
· 严禁编造：人名、数字、引语、时间、因果，凡素材没有的一律不写。宁可短，不可假。
· 看到「各家标题」列出多家媒体对同一事件的不同标题时：若措辞/归因/立场明显不同，在【深层逻辑】里点出"谁在怎么说"。
· 看到「近期已报道」清单中出现过的事件：以「📈 进展」开头，一句话交代"此前→现在→变化意味着什么"，不要当新事件从头讲。仅当确为同一事件时才这样做，不确定就当新事件。
· 看到「🎯 个人雷达命中」标记的条目：【后市/影响】必须落到对上述读者画像的**具体**影响（显卡价格、工具链变化、可上手的新东西、出海/合规影响），不许写泛泛的"利好行业"。

【每条新闻的标记与格式】
标题行：**{重要性标记} {中文标题}**
　重要性标记规则（可叠加）：🔥=被3+家媒体报道或极高重要性；⭐⭐⭐=必读 / ⭐⭐=值得看 / ⭐=速览；
　　若命中个人雷达，标题再加 🎯；若是旧事件进展，标题再加 📈。
正文三段（严格保留小标题）：
- **【核心事实】**：1-2 句概括"发生了什么"及核心数据。
- **【深层逻辑】**：事件背后的动机/商业逻辑/争议点；多家框架不同处点出立场差异。
- **【后市/影响】**：主编判断。结合本土化视角与读者画像，点明对国内市场/出海产业/宏观/该读者的潜在影响。
信息密度标签：📖 深度（有完整正文）或 📡 快讯（仅摘要/参考源）。
末行来源（不可省略）：> 📰 来源：媒体名（原文链接）

【硬性要求】
· 全程中文，专有名词首次出现可附英文原名。
· 三段式结构严格保持，点评要有信息增量和观点。
· 每条「📰 来源」必须写明媒体名和原文链接，一条都不能省。
· 仅单一来源的独家报道，在点评末尾注明「⚠️ 单一信源」。
```

### 5.5.4 实现要点（函数侧）

1. **读者画像**直接写死在 base 字符串里（上面已含），无需参数化——它就是这个项目主人的画像。若将来要给别人用，再抽成 `READER_PERSONA` 常量。
2. **「近期已报道事件清单」**由 §4.1 的 `load_recent_digests()` 生成，拼到 **user prompt**（不是 system prompt），格式：
   ```text
   ## 近期已报道事件（用于判断"进展"，勿当新事件重写）
   - [06-10] 美联储暗示年内或降息一次
   - [06-10] 英伟达发布 RTX 50 系移动版
   ...
   ```
   清单为空（首次运行/无存档）时，整段省略，并相应去掉提示词里依赖它的措辞——简单做法是清单为空时 user prompt 不附该段，AI 看到没有清单自然不会标 📈。
3. **立场交叉的「各家标题」**和**个人雷达的「🎯 命中」**由 §4.2 / §5 改造后的 `_articles_to_text` 注入到每条素材里，AI 据标记触发对应写法。
4. **分批模式**（`is_batch=True`）同样使用新 base（含读者画像与标记规则），只是不输出导语/编辑手记/审计块——保持现有分批逻辑不变。

### 5.5.5 `sanity_check_output` 配套新增

提示词要求的新东西，输出端要能粗检：

```python
# 在 sanity_check_output 里追加：
# a) 📈 进展占比过高 → 多半是 AI 把无关新闻硬接到旧事件
progress = len(re.findall(r'📈', content))
total_items = len(re.findall(r'📰\s*来源', content)) or 1
if progress / total_items > 0.5:
    warnings.append(f"📈进展条目占比 {progress}/{total_items} 过半，疑似误接旧事件")
# b) 🎯 个人雷达至少应有 0 条也正常，但若 PERSONAL_KEYWORDS 当期有命中却 0 个 🎯 → 由调用方比对（可选）
```

## 7. 验收指标（怎么知道有没有变好）

| 指标 | 现状基线 | 目标 | 测量方式 |
|---|---|---|---|
| 非大众媒体条目占比 | 0%（HN 除外约 5%） | ≥30% | 数晨报里来源标注 |
| 「📈 进展」条目 | 0 | 每期 1-3 条 | 数标记 |
| 「🎯 个人雷达」条目 | 0 | 每期 ≥1 条 | 数标记 |
| 立场差异点评 | 0 | 多源簇中 ≥50% 有 | 人工抽查 |
| 单期 token 成本 | 基线 | ≤ +30% | DeepSeek 后台用量 |
| 主观测试 | — | 每期至少 1 条「中文媒体还没写的事」 | 收到推送后拿标题搜微信/百度 |

最后一条是终极标准：**收到晨报后随手搜一条，如果中文互联网已经铺天盖地，说明这条没有信息差。**

## 8. 风险与权衡

| 风险 | 影响 | 对策 |
|---|---|---|
| 垂直源 RSS 失效/改版 | 静默少抓一层信息 | test_rss.py 进 CI，每周自动跑一次连通性 |
| arXiv/Reddit 量大冲垮候选池 | 晨报变成论文摘要 | feed 级 max_items + 观察 MIN_PER_CATEGORY |
| 跨天记忆导致 AI 误接事件 | 编造"进展"=新型幻觉 | sanity_check 统计进展占比；提示词强调"仅当确为同一事件" |
| 个人关键词过宽 | 每期被游戏新闻占满 | +4 只影响进候选池，AI 仍有否决权；定期修剪关键词表 |
| token 成本失控 | 月费上涨 | 各项增量已估算（合计 <+30%），DeepSeek 后台月度核对 |
