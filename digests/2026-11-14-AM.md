## 💡 信息差侦察 · 今日认知增量

### 1. PQ-R：面向 CPU 的 8-bit 量化新方法，SNR 提升约 3 倍（llama.cpp Discussion #16173）
**为何有价值**：本地大模型部署的实际瓶颈是量化精度与 CPU 推理速度的折中。PQ-R（Product Quantization with Residuals）声称在 TinyLlama 复杂层上做到 34dB+ SNR，而标准 INT8 只有 ~25dB，且算法按 CPU 效率设计，不走全 K-Means 的重路径。对关注 Ollama/llama.cpp/GGUF/本地部署的读者，这可能直接改写「8-bit 够不够用」的默认假设，必要时可以自己复现 benchmark。
**为何被低估**：内容只存在于 llama.cpp 的 GitHub Discussion 里，是一篇个人开发者发的实验贴，没有公司 PR、没有媒体转述，也不在 Hacker News 头版；量化领域的注意力基本被 Unsloth Dynamic 2.0 这类有品牌的方法吸走。
🔗 https://github.com/ggml-org/llama.cpp/discussions/16173

### 2. MCP 服务器可以在你「使用之前」就攻击你（Trail of Bits）
**为何有价值**：这揭穿了一个普遍的误解：用户以为只要不批准工具调用就安全。实际上 MCP 的 tool description、server metadata 在被客户端加载或索引阶段就可能被恶意构造，导致在没有实际调用工具的情况下发生信息泄露或指令注入。对正在写 agent、接入 Cursor/Claude Code、自建 MCP server 的读者，这是必须知道的设计层面威胁模型，而不只是「runtime 调用要小心」的常识。
**为何被低估**：发布于安全圈内的专业博客，讨论集中在 MCP 协议规范与客户端实现细节，主流科技媒体几乎只报「MCP 很火、生态爆发」，很少报道这类先于调用的攻击面。
🔗 https://blog.trailofbits.com/2025/04/21/jumping-the-line-how-mcp-servers-can-attack-you-before-you-ever-use-them/

### 3. Toxic Flows：多 Agent 与 MCP 之间的跨信任边界提示注入漏洞类（Invariant Labs）
**为何有价值**：把提示注入从单一的「一个模型被骗」提升到「数据在多个 agent 和 MCP server 之间流动时，信任边界在哪里被跨越」的系统性问题，并给出了可复现的攻击模式。对做 multi-agent、LangGraph、工具编排的读者，这比泛泛的「prompt injection 很危险」有用得多，可以直接拿来审查自己的 agent 拓扑与数据流。
**为何被低估**：属于安全厂商的漏洞披露博客，受众窄且发布在 2025 年中期，被同期大模型发布新闻完全淹没；中文技术社区几乎无系统译介。
🔗 https://invariantlabs.ai/blog/toxic-flow-analysis
