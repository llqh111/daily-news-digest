### 1. MCP Tool Poisoning in Agentic AI Frameworks: A Cross-Framework Measurement Study (arXiv 2611.03555)
**为何有价值**：首个跨框架量化 MCP 工具投毒风险的测量研究：基准测试 5 个主流 agent 框架，发现投毒成功率在不同框架间相差最高 3 倍，且『防御性措辞』的工具描述并不能可靠降低攻击成功率。对正在写 MCP server / 搭 agent 的读者是可直接落地的设计约束，还开源了 1200 条 poisoned tool 变体数据集与可复现 harness（配套工具 github.com/dynatrace-research/mcpvenom）。
**为何被低估**：属于 workshop 论文 + 1 star 的新仓库，尚未进入主流 AI 媒体报道循环；大多数人讨论 MCP 只谈能力不谈工具元数据投毒这一攻击面。
🔗 https://arxiv.org/abs/2611.03555

### 2. llama.cpp PR #30517: CUDA faster MMVQ for low-bit types
**为何有价值**：本地大模型推理最核心的低位宽矩阵-向量乘（MMVQ）在 CUDA 后端的实质加速补丁（+125/-59），直接决定 Q4/Q5 等量化模型在消费级 N 卡上的 token/s。对跑 Ollama/llama.cpp 本地模型的读者是可以立刻拉分支实测的性能增量。
**为何被低估**：纯 PR 级改动，没有benchmark 新闻稿，只在 llama.cpp 仓库与 r/LocalLLaMA 小圈子流传，主流 AI 媒体不会报道。
🔗 https://github.com/ggml-org/llama.cpp/pull/30517

### 3. From 8 Bits to 4: Sidecar, MoE, and the imatrix Trick That Worked
**为何有价值**：个人博客级别的量化实操记录：把 BF16 权重用指数调色板（SCLP8）压到 7.9GB，再结合 Sidecar、MoE 结构与 imatrix 激活统计做 4bit 量化，给出逐步做法与踩坑，正好补上『imatrix 到底怎么用、MoE 模型量化为何特殊』这类文档缺失的工程细节。
