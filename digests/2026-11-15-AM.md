## 💡 信息差侦察 · 今日认知增量

### 1. SEP-1686：给 MCP 加上原生长时异步任务（Call Now, Fetch Later）
**为何有价值**：MCP 目前最大的工程痛点之一是所有工具调用都是同步阻塞的——一旦 server 要跑几十秒的构建、爬取、长链推理，client 只能干等或超时。SEP-1686 提出 first-class 的 task handle 语义：server 立即返回任务句柄，client 可轮询或订阅进度/结果。这直接决定 agent 编排层的写法（重试、断点续跑、多 agent 并行调度、成本控制），对正在用 Claude Code/Cursor 或自建 LangGraph + MCP 工具链的读者是架构级变化，而不只是 API 细节。配合 Substack 上 Adam Azzam 的解读可以快速看懂设计权衡。
**为何被低估**：这条藏在 modelcontextprotocol 仓库的 issue 和一个个人 Substack 里，官方一周年 spec 通稿的媒体报道基本只讲『MCP 一岁了 + registry + SDK』，几乎没人拆解任务编排语义对 agent 架构的实际影响。
🔗 https://github.com/modelcontextprotocol/modelcontextprotocol/issues/1686

### 2. Invariant Labs「Toxic Flows」：MCP/agent 工具链的跨工具数据外泄攻击面
**为何有价值**：这不是又一个『prompt injection 存在』的通告，而是提出了一类新漏洞：单个工具本身无害，但当 agent 把 A 工具的输出当参数喂给 B 工具（比如读本地文件 → 发 HTTP 请求），数据就在『合法调用』中流出去了。对任何在写 MCP server、给 agent 接工具、或做 RAG + function calling 的读者，这意味着安全边界必须画在『数据流』层面而非单个工具层——直接影响工具权限设计、参数白名单、human-in-the-loop 审批点的放置。研究方是 Snyk 旗下团队，且明确指出 Cursor/Claude/ChatGPT 类客户端目前基本无缓解措施。
**为何被低估**：2025 年 4 月那波『MCP tool poisoning』被 Simon Willison、Trail of Bits 等带火过一轮，但 7 月底这篇 Toxic Flows 的传播量小得多，而它描述的跨工具数据流攻击恰恰是真实 agent 工作流里更难防的那类。
🔗 https://invariantlabs.ai/blog/toxic-flow-analysis

### 3. MCP Apps 扩展提案：让 MCP server 返回可交互 UI 而不只是文本
**为何有价值**：现有 MCP 交互是纯文本/JSON 往返，凡是需要人做选择的场景（确认一笔转账、挑选一个图表区间、审核 agent 生成的 diff）都得靠 prompt 里塞选项。MCP Apps 提案让 server 端直接下发交互式 UI 组件，等于把 agent 的『人机协作界面』下沉到协议层。对做 AI 编程工具、agent 前端、以及想把内部工具快速 agent 化的读者，这是能省掉一整层自研 UI 协议的机会；也值得关注它和 Claude/ChatGPT 类宿主客户端的渲染沙箱安全问题怎么解。
**为何被低估**：官方博客发布（2025-11-21）几乎紧贴一周年 spec，被 spec 通稿的注意力淹没，且它只是 extension proposal 而非正式规范，主流科技媒体没跟进。
🔗 https://blog.modelcontextprotocol.io/posts/2025-11-21-mcp-apps/
