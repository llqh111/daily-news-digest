## 💡 信息差侦察 · 今日认知增量

### 1. Agentic Coding Things That Didn't Work（Armin Ronacher / Flask 作者）
**为何有价值**：反主流叙事的第一手踩坑清单，直接反驳当下被热炒的四个观念：1)「放手让 Agent 长跑」是最大误区——有效工作单元其实只有 15-30 分钟，越无人监督越会把小错累积成难拆的大改动；2) 上下文「质量」比「容量」重要，把大代码库塞进窗口反而稀释注意力，选好检索和 CLAUDE.md 更关键；3) 子代理/多代理编排被严重高估，缺乏共享状态、父代理协调成本高，很多任务用一个范围清晰的单代理+好测试集更优；4) MCP 常带来延迟和复杂度却无对等收益，简单 CLI 工具+Agent 的 bash 能力往往更可靠。对正在学 Claude Code/Cursor、搭 Agent 的读者是可直接落地的反直觉指南。
**为何被低估**：来自个人博客（lucumr.pocoo.org），非论文/大厂公告，主流科技媒体几乎不报道「失败模式」类内容；但它比铺天盖地的『让 Agent 自主运行』吹捧更接近真实工程经验。
🔗 https://lucumr.pocoo.org/2025/7/30/things-that-didnt-work/

### 2. Orchestrating Sub-Agent Workflows with Claude Code（Matt Richards）
**为何有价值**：把 Claude Code 从『增强版自动补全』重构为『子代理工作流编排器』的一手实践，作者还顺手写了 Swift SDK。契合读者对 multi-agent / agentic 编排、MCP、工具调用的关注，提供与『子代理被高估』相反视角的具体编排思路，可对照 Armin 的批评做辩证吸收。
**为何被低估**：个人站点的长文随笔（约 2900 词），无媒体转载，属于典型藏在个人博客里的高信息密度实践记录，需主动挖掘才能看到。
🔗 https://ma.tthew.berlin/words/orchestrating-sub-agent-workflows-with-claude-code/
