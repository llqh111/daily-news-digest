### 1. MCP 2025-11-25 新版规范 changelog：sampling 支持工具调用、URL 模式 elicitation、OIDC Discovery
**为何有价值**：这是 MCP 自 2025-06-18 以来最大的一次规范升级，直接决定你写的 Agent/工具服务器能做什么：sampling 新增 tools/toolChoice 参数意味着服务端可反向让客户端模型执行工具调用（多 agent 协作的关键拼图）；SEP-1036 的 URL 模式 elicitation 让敏感操作（如 OAuth 授权、支付确认）可以跳出聊天流走浏览器；新增 icons 元数据改善工具在 UI 中的可发现性；授权服务器发现支持 OpenID Connect Discovery 1.0，可直接对接现有企业 IdP。对正在用 Claude Code/Cursor 或自建 MCP server 的读者，这些是能立刻影响架构设计的细节。
**为何被低估**：规范以 changelog + SEP 编号形式发布，属于一手技术文档，主流科技媒体通常只报道 MCP 一周年这种叙事性新闻，不会逐条拆解协议改动；国内中文技术社区对 11-25 版本的跟进更少。
🔗 https://modelcontextprotocol.io/specification/2025-11-25/changelog

### 2. MCP 授权规范转向「增量式 scope 同意」：从一次性大权限到按工具调用逐次申请
**为何有价值**：这是生产级 MCP server 的安全范式转变：过去是「一次认证、拿一大把 scope」，现在通过 WWW-Authenticate 挑战在运行时按需申请增量 scope（SEP-835），并配合 resource indicators / audience-bound token 降低 token 被滥用的风险。对要上线 MCP 服务或做企业内 Agent 平台的人，这直接关系到安全评审能否通过，也解释了为什么很多 demo 级 MCP server 在企业环境跑不起来。
**为何被低估**：该细节散落在规范 PR 与个人技术博客中（作者 Aaron Parecki 是 OAuth 领域专家），没有大媒体放大，但它是 Agent 落地企业时最先被卡住的环节。
🔗 https://den.dev/blog/mcp-november-authorization-spec/

### 3. MCP 一周年路线图信号：长时/异步任务、资源发现、agent 互操作性
